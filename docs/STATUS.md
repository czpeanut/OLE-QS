## 一句話

擷取管線與題庫應用的主幹都能運作，題庫已收錄 **6176 題**，涵蓋 9 個縣市、51 所學校、

## 已完成

**擷取管線**（`scripts/`）
- `pdf_ingest.py` — PDF 分流：原生數位／掃描／空白頁，圖形以頁面區域渲染取出
- `extract.py` — 原生數位卷 → 結構化題目；含雙欄閱讀順序、表格版面還原、答案掛載
- `canonicalize_schools.py` — 跨批次統一校名，讓一所學校在題庫裡只有一個名字
- `parse_answer_key.py` — 答案卷解析，支援四種版型，排除配分表與空白答案卷
- `validate_extraction.py` — 結構驗證（配分總和、題號連續性、選項、共用素材）
- `generate_answers.py` — 多模型交叉作答，可跑整個題庫並把答案寫回擷取結果
  （**已寫好，尚未實跑，需 API key**）

**應用**（`apps/api/`）
- 資料模型、SQLite + FTS5 trigram 中文搜尋
- 品管閘門、匯入器、Markdown+LaTeX 渲染
- REST API、單頁介面（檢索 → 題籃 → 匯出三種卷）

## 關鍵決策（**動手改之前先讀這段**）

這些不是隨意選的，都是撞牆撞出來的。改動前請確認你理解原因。

| 決策 | 為什麼 |
|---|---|
| **捨棄有問題的題目，不做人工校對** | 來源卷很多、題目可替換，丟一題的成本遠低於人工修好它。這個決定讓原本估計 17 小時的校對工作消失 |
| **出處掛在題目上，不是文件上** | 題庫的用途是跨卷重組。存在文件層的話，去重合併、改編題、原文件被刪都會讓出處失效 |
| **被剔除的題目保留不刪除** | 剔除率是管線健康度指標；從 8% 跳到 40% 代表管線壞了，不是卷變難了 |
| **路徑優先於卷頭解析（年級除外）** | 很多考卷不印學校與學年度，那些資訊只在目錄慣例裡。但**年級不在路徑裡**，只能靠卷面 |
| **目錄的 `1-2` 是「學期-次數」** | 見下節。這一條曾經被讀反過，污染了整批資料 |
| **年級取「離『學年度』最近的那個」** | 一頁上常有好幾個年級：題目內文的「某校二年級學生…」、學校忘了換掉的上屆頁首。卷名才是這份卷的年級 |
| **一所學校只能有一個校名** | 同校相鄰兩次段考會寫成「石門國中」與「石門國民中學」，照抄的話檢索與統計會把一所學校算成兩所 |
| **原生數位 PDF 不轉圖再 OCR** | 文字圖層可無損取出。轉圖再辨識是把已經正確的文字弄髒再猜回來 |
| **圖形用頁面區域渲染，不抽 XObject** | 抽取會丟失 SMask 導致整張變黑，且同一張圖被重複放置時只會拿到一張 |
| **規則式擷取，不用模型** | 考卷版面規律性高；規則涵蓋不到的由品管閘門剔除。**寧可漏抓，不可錯抓** |
| **卷面沒印的科目／年級用旗標明示，不猜** | `--subject`／`--grade` 是人工宣告的批次事實，會出現在指令裡；程式自己猜則無從查核 |

### 目錄慣例被讀反過（處理 111／112 批時發現）

目錄是 `學年度／學期-次數／縣市／學校.pdf`，`1-2` ＝ **第 1 學期第 2 次段考**。
舊版 `parse_path` 讀成「1 年級第 2 學期」。三個證據：

- 一個學年只有兩個學期，但目錄裡有 `1-3`、`2-3`，年級解讀擺不下。
- 卷頭寫得很清楚：「彰化縣立溪湖國中111學年度第一學期第三次段考 一年級數學科試卷」。
- 後來補進來的 113 批就是以 `1-3`、`2-1`、`2-2`、`2-3` 四包分裝的，和 `1-1`、`1-2`
  湊成完整的六次段考。

影響到已經入庫的 113 批：`_72` 那 30 份被標成「第 2 學期」，實際是第 1 學期第 2 次段考
（它們的命題範圍寫著「康軒版**第一冊**第 2 章」，第一冊＝七上，可以佐證）。
學期會印進題目的出處引用，所以這是實質錯誤。年級因為數字 1 恰好對應七年級而沒出錯，
但那是巧合而非推導。

> 這批後來拿到原始 PDF 重跑了，所以現在庫裡的是新管線的輸出，不是修補過的舊資料。
> 同一批卷舊管線抽到 941 題、新管線 1469 題，另外多救回 8 份舊管線完全失敗的卷；
> 原本 200 題「未分類」也全部正確歸為數學 —— 那是舊科目規則切壞的，不是真的分不出來。

修正後文件 ID 改為 `doc_{學年度}_{縣市}_{學校}_{科目}_g{年級}s{學期}e{次數}`。
舊格式只有年級＋學期，同校同學期的 3 次段考、同一次段考的 5 個科目都會撞成同一個
ID，後匯入的直接覆蓋前一份。

## 下一步（依價值排序）

1. **補答案** — 326/6176 是壓倒性的最大短板，而且題庫變大之後比例更難看。
   兩條路：去要答案卷（最可靠，同時是量測 AI 準確率的校準資料），
   或跑 `generate_answers.py`（需 `GEMINI_API_KEY` + `ANTHROPIC_API_KEY`）：

   ```bash
   python scripts/generate_answers.py data/bank --figures data/assets --merge
   ```

   實際要送模型的是 **5850 題** —— 已有答案的 354 題不重跑（答案卷的答案是確認過的，
   不該被模型覆蓋），品管閘門會剔除的 1038 題也不送（那些題目不會出現在檢索組卷裡）。

   **模型作答一律標為 `ai_generated`，不是 `verified`。** 只有答案卷與人工能給
   verified；兩個模型都同意提高的是可信度，不是確認。教師解答卷會把未確認的答案
   標出來 —— 那份卷是拿來改分的，印得跟正解一樣等於把「不知道錯在哪」交給老師。
2. **掃描件路線** — 三批共 **43 份**掃描 PDF 完全沒有文字圖層，一題都取不到
   （彰化福興 13、埤頭 9、台南復興 6、基隆銘傳 5、高雄五甲 4 是大宗）。需要 VLM 擷取
3. **拿 114 批的原始 PDF 重跑** — 那 5 份是唯一還用有缺陷管線抽的資料
   （見下節），原始 PDF 不在版控裡
4. **看那 1066 題為什麼被剔除** — 資料都在（`status='rejected'` 帶原因），
   最大宗集中在選項：選項數不符、選項標籤重複、選項空白。
   集中在選項代表問題出在選項切分而不是題目本身，值得為它加規則
5. **課綱分類表** — 現在的分類標籤是擷取到的章節名，尚未對應 108 課綱正式代碼
6. Word 匯出、智慧組卷（依權重自動抽題）

## 這次修掉的擷取缺陷

前四個都是「整份卷幾乎抓不到題目」等級的，不是邊際改善：

| 缺陷 | 症狀 |
|---|---|
| 答案頁判定看整頁 | 「請在**答案卷**上作答」是題目卷最常見的注意事項，整份卷被當成答案頁丟掉（埔心 0 題） |
| 題號只認「數字在前」 | 這批大量是 `(     ) 1. …`，括號在前。誠正 23 題只抓到 3 題 |
| 年級寫法只認「一二三年級」 | 還有「七年級」「1年級」「國一」「【七】年級」「七學級」，林園 12 份全數被跳過 |
| 科目取「科」字前面 1~3 個字 | 切出「考數學」「級數學」，同一科在題庫裡有三種寫法 |
| 校名前面黏字就整段放棄 | 「學期臺中市立向上國民中學」——縣市改成直接列舉比對 |
| 年級取第一個命中 | 有學校頁首留著上一屆的「九年級數學」，卷名卻是「(七年級)」，七年級卷被歸成九年級 |
| 整頁文字被存成小圖時照單全收 | 有考卷把每個字存成 12×12 影像（單頁 15598 個置放），一題掛上 2777 張圖，圖檔目錄膨脹到 241MB |

加上三個穩定性問題：退化的圖形區域會讓整批中斷（現在略過該圖）、
一題都沒抓到的卷會寫出空文件（現在直接跳過並報出來）、
`(A) 1.5 公尺` 這種選項裡的小數會被當成第 1 題（現在要求題號後面不接數字）。

## 已知問題

- **答案覆蓋率 5%** — 多數卷是純題目卷，沒附答案
- **掃描件未支援** —— 三批 336 份裡有 43 份是掃描件
- **114 批那 5 份是用有缺陷的管線抽的**，原始 PDF 不在版控裡，無法重跑
- 有 1 份卷（新北土城 113-1-3）的 PDF 字元對映壞掉（`x` 變成 `ݔ`，題號不在文字層裡），
  無法擷取，已跳過
- 分類標籤未對應正式課綱代碼
- 校名跨批次統一目前是獨立步驟（`canonicalize_schools.py`），不是匯入時自動做
