## 2. 單元表（交付物 A）

### 2.1 「冊」怎麼定

高中卷要先決定題目屬於哪一冊，才能選節。資料裡的 `document.course`、`grade`、`semester` 有這些組合（括號是卷數）：

- **選修課（有 `course`）**：冊就是 `course` 本身，**不要看年級**。
  - 同一門選修在不同學校排在不同年級，例如選修生物I 在高一、高二、高三都出現過。
  - 有：選修物理I～V、選修化學I～V、選修生物I／II／III／V、選修歷史I／II、選修地理I／II、選修公民與社會I／II。
  - 數學：數A、數B（高二）；數甲、數乙（高三）。
- **必修課（沒有 `course`）**：依年級、學期對應必修冊，例如數學高一上＝第一冊、高一下＝第二冊；歷史、地理、公民高一～高二各冊。
  - 學校可能把必修冊挪到別的學期上，判斷時以下列兩項為準：
    - 卷上印的考試範圍 `document.scope_note`，595 份卷有；
    - 題目內容本身。
- 自然科的必修是「基礎物理／基礎化學／基礎生物／基礎地科」，各校在高一、高二的排法不同，一樣以 `scope_note` 和內容為準。

### 2.2 格式

照 `junior.yaml` 的結構，最上層改成科目 → 冊 → 出版社 → 節：

```yaml
source: <資料來源網址或書目>
note: 108 課綱高中版本對照表
subjects:
  數學:
    第一冊:            # 必修冊；選修用 course 原字，例如「數A 第三冊」「選修物理I」
      龍騰:
      - chapter: 1
        chapter_title: 數與式
        section: 1-1
        title: 實數
```

- 節（section）是最小單位，國文用課。
- 出版社列入高中主要版本（龍騰、翰林、南一、康熹、全華等），**以實際查得的目錄為準，不要憑記憶補**。
- `source` 寫明出處。查不到的冊寫 `TODO`，列進報告。
- 各家目錄同一主題的名稱不同時，另外加一個不分版本的「標準單元」欄 `std: <冊>-<序號>`，題型目錄與統計都用它，才不會同一主題被拆成好幾份。

## 3. 歸章節（交付物 C）

做法照 `scripts/classify_chapters.py`：

1. 一份卷呼叫一次模型，送出：
   - 該卷那一冊各版本的章節列表；
   - `scope_note`（考試範圍）；
   - 全卷題目的精簡文字（題組附上題組文章）。
2. 模型先判斷這份卷用哪個版本，再逐題選節。卷上有印版本時，只給那個版本的列表。
3. 規則：
   - 題目必須落在考試範圍內。範圍外的只有在明顯是跨章綜合題時才可以，並在 `note` 說明。
   - 題組的子題原則上同一節。
   - 判斷不了就寫 `section: null` 並寫原因，**不要硬猜**。
   - 「承上題」要一起看前一題。

輸出每題一行：

```json
{"id": "doc_..._s1_3", "book": "第一冊", "publisher": "龍騰", "std": "第一冊-2", "section": "1-2", "title": "…", "chapter": "第1章 …", "confidence": "high|medium|low", "note": ""}
```

## 4. 題型目錄與歸類（交付物 B、D）

做法照 `scripts/math_patterns.py`，分三步：

1. **歸納（discover）**
   - 每個標準單元抽最多 300 題送模型，歸納出 8～20 個題型。
   - 每個題型有代號 `T01`…、名稱、一句話說明（怎麼考、要用什麼方法），格式同 `math_patterns/7-1_1-1.yaml`。
   - 題型要依「解法」分，不是依情境分。
2. **歸類（classify）**
   - 每題選一個題型，加難度 1～5。
   - 歸不進的寫 `OTHER`。
   - 題目附圖要一起送給模型，題組附上題組文章。
3. **修整（refine）**
   - 單元裡 `OTHER` 超過 10%：從這些題補新題型。
   - 單一題型超過 30%：太雜，要拆開。
   - 修整後重歸受影響的題。

題型目錄檔：

```yaml
unit: {subject: 數學, book: 第一冊, std: 第一冊-2, title: …}
status: draft
sampled: 300
unit_questions: 612
types:
- code: T01
  name: …
  desc: …
```

題型標註每題一行：

```json
{"id": "doc_..._s1_3", "std": "第一冊-2", "pattern": "T04", "difficulty": 3}
```

## 5. 自我抽驗（交件前必做）

- 每科隨機抽 50 題（固定種子 20261117），人工對原卷判斷章節與題型是否正確，結果寫進 `REPORT.md`，每題附 id。
  - 錯誤超過 5% 的科目要修正規則後重跑。
- 覆蓋率表：每科 `section: null` 與 `OTHER` 各多少、原因分布。
- 抽查題組：同一題組被分到不同節的，全部列出。
- 督察收件後每科再抽 30 題；錯誤超過 5% 退回。

## 6. 費用（先估算、經同意才跑）

- 用便宜的模型與批次 API（國中做法是 Gemini Flash 系列、批次半價）。
- 呼叫次數：
  - 章節：每份卷 1 次，約 1,500 次；
  - 題型歸納：每單元 1 次；
  - 題型歸類：每題或每批題目 1 次。
- 開跑前交估算：
  - 用 3 份卷、1 個單元試跑，量實際的輸入／輸出 token 數，推估全量費用（新台幣）。
  - 寫在進度回報，**等題庫負責人同意**。
- 每個程式都要有花費帳本與上限（照 `classify_chapters.py` 的 `--ledger`、`--budget-twd`），超過上限自動停。

## 7. 交件與順序

1. 先交 A（單元表）。督察看過格式與來源後才做 C、D。
2. 依序：數學 → 物理 → 化學 → 生物 → 地科 → 歷史 → 地理 → 公民 → 國文，每科做完交一次。
3. 交件放雲端「第三輪交件」：
   - 檔名 `UNITS_<科目>.zip`，內含該科的 B、C、D 與 `REPORT.md`；
   - 單元表另交 `senior.yaml`；
   - 每段 ≤5MB。
4. 進度回報寫一筆：科目、題數、`section: null` 與 `OTHER` 比例、自我抽驗錯誤數、花費。

## 8. 停下來回報的情況

- 某一冊在任何出版社都查不到目錄。
- 某科超過 15% 題目歸不到章節。
- 花費會超過已核可的上限。

其他問題（個別題目判斷不了、題型難分）照規則標 `null`／`OTHER` 照交，不要停工。
