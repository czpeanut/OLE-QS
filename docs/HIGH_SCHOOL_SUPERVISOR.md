## 3. 每批自驗（交關卡前必做，G3 也照做）

1. **檢查程式**（3.1 版）結束碼 0：

   ```bash
   python scripts/check_bank_yaml.py high_school/bank --assets high_school/assets \
     --sources high_school/sources --existing --strict --issues-csv high_school/剩餘問題.csv \
     > high_school/check_report.txt
   ```

   有 `waivers` 的，逐條確認理由成立。

2. **`round3_qa.py`**（新工具，在交接包 `scripts/`）：拿原始 Word 檔比對，結尾必須是「0 份有短少」：

   ```bash
   python scripts/round3_qa.py --batch <這批原始 .doc 所在資料夾> high_school/bank > high_school/qa_report.txt
   ```

   - 規則 A：原卷加括號的代號（(甲)、(二)…）在 YAML 裡有沒有括號，會列出缺的題號。
   - 規則 B：原卷畫底線的文字有沒有轉成 `<u>`。需要 LibreOffice；它會自動把 .doc 轉成 .docx。
   - 原始檔請給 .doc。.docx 會失去 EQ 欄位，規則 A 查不到。

3. **人工抽查**：每批隨機抽 10 題，打開原卷 PDF 逐字核對：
   - 題幹、選項、表格、題組材料、公式；
   - 答案；
   - 附圖有沒有掛對題。

   抽查結果寫進驗收單；**錯 1 題就整批退回執行 agent**。
4. **解析器要改、不准手改**：發現的錯誤一律回到解析器修正後整批重新產生，再從第 1 步重跑。

## 4. 驗收單與上呈

**監工驗收單**：每批一份，放在該批 zip 裡的 `SUPERVISOR_QA.md`，並在「ROUND3_進度回報」登記一行。內容：

- 批次名稱、卷數、題數、附圖數；
- `check_report.txt` 最後兩行、`qa_report.txt` 最後一行；
- `waivers` 清單（沒有寫「無」）；
- 人工抽查的 10 個題目 id 與結果；
- 已知但還沒解決的問題（沒有寫「無」）。

**上呈督察**：只有下列三種情況才上呈。寫在「ROUND3_進度回報」最上方的「督察請示」區，督察在下一次關卡進場時回覆。

- 規則互相衝突；
- 規則沒涵蓋到的情況；
- 檢查工具誤判，而且無法用 waivers 處理。

會擋住所有工作的急事，請使用者轉達。
